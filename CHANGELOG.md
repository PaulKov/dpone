  `Popen.communicate(...)` lifecycle instead of creating stdout/stderr reader
  threads for every import. Asynchronous `queryout` keeps concurrent pipe
  drainers because its FIFO consumer runs before process wait, but terminal
  drain and abort cleanup are both finite. Repeated import/ODBC certification

  `runtime.storage.work_dir` through the runtime composition root. The sink
  provisions and descriptor-pins that directory before proven row-stream
  extraction, then reopens it immediately before spooling. File creation and
  cleanup use descriptor-relative exclusive operations on POSIX. Windows holds
  verified non-delete-sharing handles for the complete resolved path chain
  while performing exclusive file operations, providing the same rename and
  ancestor-swap exclusion without requiring `dir_fd`. The completed file
  remains pinned through BCP as well: POSIX creates an unnamed file (or removes
  its exclusive random basename in the portable fallback) before source
  iteration, retains separate writer and read-only descriptors, removes write
  permissions after serialization, then captures, verifies, and consumes the
  held reader through its `/proc/self/fd` or `/dev/fd` projection; cleanup only
  closes that descriptor and therefore cannot delete a later pathname
  replacement. Windows retains a read identity whose creation-time sharing
  contract denies write and delete opens while allowing BCP's concurrent
  reader, then deletes only a reopened handle whose volume/file identity,
  creation timestamp, and final path still match. Receipt SHA-256, BCP input,
  and consumed-payload
  evidence now share that one pinned identity. The exact UTF-8 logical-file
  cap preserves the configured `min_free_bytes` reserve; partial-write cleanup
  failures publish stable, path-free residue evidence without replacing the
  primary failure, and directory-handle release failures use a distinct stable
  code without falsely asserting file residue.
  Native, typed-file, query, and other non-spool routes no longer receive an
  implicit 1 GiB spool floor. Manifests without explicit storage keep the
  documented system-temporary-directory fallback and warning; live route
  certification remains separate from these mechanism tests. Runtime
  components sharing the task's OS identity remain inside the trusted process
  boundary: POSIX mode bits, early anonymization, and descriptor pinning
  prevent pathname rebinding but are not an fs-verity-style seal against a
  hostile same-UID process that can inspect or mutate another process's open
  descriptors.
- MSSQL staging-authority lease admission now retries only an exact closed set
  of transient ODBC connection SQLSTATEs, twice with fixed 5/10-second backoff
  inside a 45-second pre-mutation deadline. Every attempt owns fresh staging
  and master sessions and closes both before retry; authentication,
  configuration, cancellation, permission, signed-pin, topology and
  current-database failures remain fail-fast. Exhausted errors retain their
  stable public code and emit only sanitized stage/SQLSTATE/attempt evidence,
  never raw driver diagnostics.
- Dpone KubernetesPodOperator tasks now treat an exhausted retryable
  Kubernetes live-log HTTP `429`/`500`/`502`/`503`/`504` as an observability
  degradation, not as proof that the runtime container failed. The affected
  task attempt emits one bounded
  `DPONE_KPO_LOG_STREAM_DEGRADED` marker and switches to the provider's normal

## 0.74.27 - 2026-08-24

### Added

- Target-atomic MSSQL initial backfills now run fixed, long-lived lanes in
  isolated `spawn` processes. Each lane owns its PostgreSQL/MSSQL runtime while
  the parent alone owns dispatch, ledger transitions, campaign/chunk leases,
  operation-lease IPC and receipt reconciliation. Four configured workers can
  therefore transfer four chunks concurrently without sharing pyodbc state or
  relying on Python worker threads; one remaining chunk still uses the same
  process contract.
- A separate protected PyPI API-token break-glass workflow can recover an
  ordinary release only after its Trusted Publishing step fails. It reuses the
  provider-bound eight-file candidate artifact without checkout or rebuild,
  requires exact tag/commit/source-run/change/reviewer/environment binding,
  accepts only an absent or byte-identical public subset for safe partial
  retry, and retains attempt-scoped authorization, publication, verification,
  and audit evidence. Its source-free verifier now shares one dependency-free,
  closed merge-receipt contract with the producer, so omitted, extra, or
  mistyped authority fields are rejected even after a binding digest is
  recomputed. Trusted Publishing remains the default release path; the ordinary
  workflow and break-glass recovery share the same hardened verifier and
  publication-authority contract.

### Fixed

- Target-atomic MSSQL snapshot recovery now distinguishes failures before the
  driver COMMIT call from acknowledgement loss after it: proven pre-COMMIT
  failures roll back target/state DML and clean staging for safe replay, while
  an unproven outcome remains fail-closed and retains forensic tables without
  retaining authority sessions. BCP processes now drain both output pipes
  concurrently, default to an overridable 3600-second deadline,
  terminate/kill/reap deterministically, and expose only redacted timeout
  commands; omitted deadlines normalize to the default and invalid explicit
  values fail before execution.
- Strict Airflow release materialization now retains the validated
  scheduler-owned `pool` and `retries` DAG overrides while continuing to remove
  legacy `in_cluster` and all executable or pod-security overrides. Immutable
  release DAG specs therefore preserve source-admission pools instead of
  silently serializing affected tasks into `default_pool`. Rollout requires a
  coordinated `dpone-airflow-pack` and `apache-airflow-providers-dpone` version
  of at least `0.74.20`.
- Character-BCP MSSQL routes can materialize `BulkTextCodec` decoding once in
  an owned raw-shaped staging table before lossless conversion validation and
  native projection. A metadata-only capacity gate admits the additional heap
  only when current free space in the database default filegroup covers decoded
