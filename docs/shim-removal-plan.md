# Shim removal plan

This document turns deprecation cleanup into a concrete, reviewable batch plan.

## Purpose

Compatibility shims are useful during migration, but they must not become permanent hidden API surface. Remove them only when the public migration path is documented and tests prove the new path works.

## How to use this plan

1. Identify a shim path and its replacement.
2. Confirm no public documentation still recommends the shim.
3. Add or update deprecation tests.
4. Remove one shim family at a time.
5. Run import, CLI, package, and documentation gates.
6. Document the removal in the changelog.

## Removal order

Recommended order:

1. Provider-specific legacy imports with direct canonical replacements.
2. CLI compatibility facades that are no longer documented.
3. Runtime facades that only forward to a canonical source or sink.
4. Test-only helpers that are no longer used.
