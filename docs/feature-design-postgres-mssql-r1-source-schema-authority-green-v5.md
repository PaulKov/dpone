## Detailed algorithm

### Terminal state and ownership

Exactly one caller atomically claims terminal ownership. Concurrent terminal
callers wait and observe the same immutable receipt; their own cancellation
does not transfer cleanup ownership. Rollback, quarantine and issuer release
each run at most once.

The receipt has independent axes:

```yaml
outcome: completed | aborted
cleanup_succeeded: true | false
cleanup_error_reason: null | snapshot_cleanup_failed
connection_quarantined: true | false
```

The closed behavior is:

| Operation | Ordinary cleanup success | Ordinary cleanup failure | Caller cancellation |
|---|---|---|---|
| `complete(artifact)` | freeze completed/clean receipt; return | freeze `outcome=completed`, cleanup failed/quarantined; raise `snapshot_cleanup_failed` | owner freezes truthful receipt after one cleanup attempt, then re-raises the identical cancellation; waiter re-raises its own identical cancellation |
| `abort_preserving(primary)` | freeze aborted receipt; re-raise identical primary | freeze aborted, cleanup failed/quarantined; re-raise identical primary | an existing primary wins; otherwise the owning cancellation is re-raised after receipt freeze |
| `close_if_active()` | freeze aborted/clean receipt; return `None` | freeze aborted, cleanup failed/quarantined; return `None` | the owning or waiting caller cancellation may propagate unchanged according to ownership rules |

`close_if_active()` suppresses ordinary cleanup and route errors from a
`finally` path; it does **not** swallow caller cancellation. Returning `None`
is never target-visible success. Receipt construction and freeze are
synchronous, dependency-free and non-cancellable.

Every broad normalization boundary must re-raise `CancelledError` by object
identity before translating ordinary exceptions. This includes document and
model decode, catalog/type resolution, projection, artifact admission,
prepared-boundary construction, active/terminal/pinned connection access,
rollback, quarantine, issuer release and the real composition path before
endpoint I/O. Raw cause/context links remain closed.

### Pseudocode

```text
terminal_call(operation):
  decision = claim_or_wait(operation)
  if decision is waiter:
    await immutable_receipt
    return operation_projection(receipt)
  try:
    validate_owner_preconditions()
    perform_lifecycle_transition()
  except CancelledError as cancellation:
    cleanup_once_and_freeze_truthful_receipt()
    raise_same(cancellation)
  except BaseException as primary:
    cleanup_once_and_freeze_truthful_receipt()
    raise_same(primary)
  try:
    cleanup_error = cleanup_once()
  except CancelledError as cancellation:
    freeze_truthful_receipt(cleanup_succeeded=false)
    release_owner_reservation_once()
    raise_same(cancellation)
  freeze_truthful_receipt(cleanup_error)
  release_owner_reservation_once()
  project_terminal_result(operation, cleanup_error)
```

### Failure and recovery

- A cleanup-only failure after lifecycle completion never reverses
  `outcome=completed`, but boundary completion raises a stable route error so
  no caller observes overall success.
- Abort/close cleanup failure quarantines the connection and preserves the
  original primary.
- Lost or replaced transaction incarnation fails closed before business read.
- Retry creates a new issuer epoch/snapshot scope; a terminal receipt is never
  reopened.
