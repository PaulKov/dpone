# v0.10.0 Release Cutover Implementation Plan

> **Historical design record.** Commands below are preserved as implementation evidence and are not current runbooks. Use [Module-size debt ratchet](../../module-size-ratchet.md) for the supported exact-SHA command.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote the stacked route certification train into a guarded `v0.10.0` release candidate without losing the already released `v0.8.0` OSS benchmark work or the current `v0.9.0` release hardening baseline.

**Architecture:** Treat this as a release-control-plane change, not a runtime connector change. The release branch stays on top of the current stacked PR train, adds only version/changelog/planning evidence, validates the full local gate suite, and publishes a rollup PR to `master`; the `v0.10.0` tag is created only after the rollup has merged and post-merge evidence is green.

**Tech Stack:** Python 3.11/3.12, uv, pytest, ruff, mypy, MkDocs, GitHub CLI, dpone ops release RC commands.

### Task 4: Generate Release Candidate Evidence

**Files:**

- Read: GitHub PR metadata for the rollup PR.
- Write local evidence only: `test_artifacts/release/v0.10.0/release-rc-collect/*` and `test_artifacts/release/v0.10.0/release-rc-finalizer/*`.

- [ ] **Step 1: Export rollup PR metadata**

Run:

```bash
mkdir -p test_artifacts/release/v0.10.0/prs
ROLLUP_PR_NUMBER="$(gh pr view codex/v0.10.0-release-cutover --json number -q .number)"
gh pr view "$ROLLUP_PR_NUMBER" \
  --json number,title,baseRefName,headRefName,state,mergeStateStatus,isDraft,url,statusCheckRollup \
  > test_artifacts/release/v0.10.0/prs/rollup-pr.json
```

Expected: the file contains the rollup PR merge state and CI conclusions.

- [ ] **Step 2: Run RC collection**

Run:

```bash
uv run dpone ops release-rc-collect \
  --release v0.10.0 \
  --previous-release v0.9.0 \
  --package-version 0.10.0 \
  --base-branch master \
  --head-branch codex/v0.10.0-release-cutover \
  --pull-request-json test_artifacts/release/v0.10.0/prs/rollup-pr.json \
  --output-dir test_artifacts/release/v0.10.0/release-rc-collect \
  --finalizer-output-dir test_artifacts/release/v0.10.0/release-rc-finalizer \
  --format json
```

Expected: the command exits with code `0` and writes `merge_train.json`, `release_rc_inputs.json`, `release_rc_collect.json`, and `release_rc_collect.md`.

- [ ] **Step 3: Run pre-merge finalizer**

Run:

```bash
uv run dpone ops release-rc-finalize \
  --release v0.10.0 \
  --previous-release v0.9.0 \
  --package-version 0.10.0 \
  --merge-train-json test_artifacts/release/v0.10.0/release-rc-collect/merge_train.json \
  --mode pre_merge \
  --output-dir test_artifacts/release/v0.10.0/release-rc-finalizer \
  --format json
```

Expected: the command exits with code `0` only after the rollup PR is clean and not draft. If CI or review state blocks it, keep the JSON/Markdown outputs as the current release blocker.
